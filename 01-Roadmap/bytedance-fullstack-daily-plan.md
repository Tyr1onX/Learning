# 字节全栈实习每日固定计划

## 总目标

面向下一次字节跳动日常实习 / 暑期实习，持续建立全栈开发、计算机基础、算法与面试表达能力。

核心原则：每天固定完成少量、明确、可结束的任务。完成当天任务后停止继续准备，避免把备战变成无休止的高压状态。

## 每日结构

每天只做两项必做任务：

1. 一个明确的全栈 / CS 学习主题；
2. 一道算法任务。

当天任务完成后即视为收工，不临时追加新的学习主题、额外算法题或大段面试资料。

## 全栈学习规则

- 每天只推进一个可在当天闭环的小主题；
- 学习顺序以当前能力断点为准，不盲目跳主题；
- 当前主线从 JavaScript 基础继续：

```text
const / let
→ 值与类型
→ 对象 / 数组
→ 函数
→ 作用域 / 闭包 / this / prototype
→ DOM / Event
→ Promise / async-await / Event Loop
→ fetch / JSON / API
→ TypeScript
→ React
→ Node.js Backend
→ SQL / Database
→ Auth / Full-stack interaction
→ Linux / Docker / Deployment / CI
```

- Web / Network / Browser 已有基础继续通过间隔回忆维持，不重复从头学习；
- 每个主题都优先做到：理解 → 自己解释 → 小练习 → 与项目连接。

## 算法规则

使用 LeetCode Hot 100 作为主要题池，但不机械按照页面顺序；按题型和当前能力重新安排顺序。

### 每天的算法量

- 正常日：1 道新题；
- 复习日：按计划复习旧题，并根据当天总量决定是否暂停上新题；
- 不因为当天状态好而额外刷题。

### 做题流程

```text
先独立思考
→ 写出最直接方案
→ 分析时间 / 空间复杂度
→ 必要时获得提示
→ 写出正确实现
→ 用自己的话解释核心思路
→ 记录错误点 / 关键模式
```

### 复习机制

一道新题进入复习池后，默认在以下节点检查：

```text
D+1：口述核心思路与复杂度
D+3：不看答案恢复关键步骤
D+7：重新独立完成或完整推导
D+21：随机抽查，确认是否真正形成题型记忆
```

复习的目标不是背代码，而是确认仍能识别题型、建立模型并独立实现。

## 每日提醒与晚间复习

每天采用“早上开始 + 晚上回忆”的双检查点：

### 早上

提醒开始当天固定的字节准备。读取 Learning 当前状态后，只安排当天既定学习主题、算法新题和到期旧题复习，不额外加量。

### 晚上

当天再进行一次短时回忆复习，但这不算新的学习任务，也不允许开启新知识：

```text
当天知识主题
→ 脱离笔记口述核心概念
→ 检查白天纠正过的易错表达

当天算法题
→ 说出题型识别信号
→ 说出核心数据结构 / 算法思路
→ 说出时间与空间复杂度
```

如果晚上忘记某个点，只标记为待复习并在后续间隔复习中重新检查，不在晚上扩展成新的长学习任务。

重要知识和算法除当天晚间回忆外，继续使用跨天间隔复习；不能因为当天晚上答对一次就视为长期掌握。

## 结束规则

当天两项必做任务完成后：

> 字节实习准备当天结束。

晚上的短时回忆仅用于巩固当天内容，不属于继续加量。除此之外，可以自由做感兴趣的项目、开源、产品、小说、视频或其他探索，但不再因为“还可以多学一点”继续追加字节备战任务。

## 每日开始方式

每天开始时，由 AI 读取当前学习状态和算法记录，直接给出当天固定任务，包括：

```text
今日学习主题
完成标准
今日算法题
需要复习的旧题（如有）
今日停止线
```

当天结束时，将实际完成情况和新的学习断点增量写回 Learning 仓库；晚间复习如果发现新的遗忘点或误区，再增量记录需要后续复查的内容。
