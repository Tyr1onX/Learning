## 项目 1：桌面课表工具

面试中介绍的核心：本地优先桌面课表，技术栈包括 Tauri、TypeScript / CSS、Rust；支持 Excel 和图片导入，OCR 后经过人工审核，再写入本地数据；不同导入来源先统一成中间草稿数据格式。

### 被追问的方向

- 为什么选择 Tauri / Rust？
- 项目是不是有服务端？数据存在哪里？
- OCR 在哪里运行，怎么调用？
- Excel / 图片两种数据如何统一？
- 前端如何拿到处理结果并展示？

### 表现较好的点

能够说出“本地优先”、人工审核、统一草稿中间格式等设计思路。这比只罗列功能更接近工程设计说明。

### 需要改进

对部分底层实现的描述仍偏“知道大概流程”，需要做到：

```text
为什么选这个方案？
↓
数据如何流动？
↓
进程 / 模块边界在哪里？
↓
失败路径是什么？
↓
为什么这样比替代方案更合适？
```

## 项目 2：个人静态网站

面试中明确说明网站是纯静态页面，主要展示项目、学习记录和思考，部署在 GitHub Pages。

### 被追问的方向

- 如果访问这个网址，从输入 URL 到页面完整渲染，会发生什么？
- 如果不用 GitHub Pages，前端项目最终产物是什么？
- 为什么断网 / 本地直接打开时部分文字内容可能缺失？
- 页面动画使用什么技术栈？
- 具体动画是如何实现的，而不只是“AI 帮我写的”？

### 暴露的问题

“输入 URL 到页面展示”回答顺序不够稳定，出现了把浏览器渲染、GET / POST、HTTPS、TCP 等概念混在一起的问题。

这直接形成当前学习主线：

[[03-Knowledge/Web/01-url-dns-tcp-tls-http]] → [[03-Knowledge/Web/02-cors-auth-security]] → [[03-Knowledge/Web/03-cache-cdn-http-versions]] → [[03-Knowledge/Web/04-browser-rendering]]

动画追问也暴露出一个重要问题：如果实现主要由 AI 生成，自己仍然必须能够解释它用了什么 API、浏览器做了什么、性能代价是什么。

## AI 辅助开发方法

面试中讨论了 AI Coding 工作流，包括：

- 先把需求和上下文说清楚；
- 通过提示词 / 程序校验约束输出格式；
- 先做 MVP，再迭代；
- 把踩坑与解决方案沉淀成文档；
- 使用不同 AI 承担开发与审查角色。

这是面试中的相对优势之一，因为回答不只是“我会用 AI”，而是已经形成了一些约束、验收、复盘意识。

但下一阶段必须把这类经验连接到传统基础：如果不了解框架、网络、安全、复杂度和工程化，就无法判断 AI 的结果究竟好不好。

## 算法题：行级 Diff

面试官给出两组新旧代码行，希望实现一个 Diff 方法，输出三类操作：

```text
keep
 delete
add
```

目标是描述如何把旧代码行转换成新代码行。

现场能理解 `keep / delete / add` 的语义，但没有形成可实现的算法方案，是本次面试最明确的算法短板之一。

### 后续学习路线

```text
序列比较问题
↓
动态规划基础
↓
LCS（Longest Common Subsequence）
↓
根据 LCS 构造 keep / delete / add
↓
理解复杂度
↓
再了解 Myers Diff
```

不要直接背 Myers；先把 LCS / DP 的基本建模能力补起来。

## 面试官给出的能力建议

以下内容是本次面试官在反问环节表达的观点，应作为“这次面试反馈”保存，不自动外推成整个行业的绝对事实。

### 1. 需求表达与结果判断

任何人都可以使用大模型完成需求，因此更关键的是能否把需求表达清楚，并判断模型结果是否安全、可用、可持续迭代。

### 2. 基础原理

需要理解框架层和基础原理，才能对 AI 生成方案做更准确的判断。

### 3. 性能与复杂度

算法有复杂度，复杂度会直接影响性能。只有自己知道这个问题存在，才知道应该要求 AI 考虑它。

### 4. 安全

需要思考前后端 / 客户端与服务端之间用户信息如何传输，以及服务端再与大模型交互时如何保证安全与可行。

### 5. 工程化与可维护性

真实生产项目可能维护五六年甚至更久，还会有多个团队 / 同学接手，因此结构、兼容性、可扩展性和可理解性都很重要。“本地能跑”远远不够。

### 6. AI Coding 与全栈趋势（面试官所在团队口径）

面试官表示其团队前端 AI 代码占比约 90%，后端约 60%～70%，并提到招聘方向正从纯前端走向全栈，以降低前后端协议沟通与业务熟悉成本。

这条信息应理解为“本次面试官所在环境的经验反馈”，而不是整个行业统一统计。

## 当前复盘结论

### 优势

```text
项目是真的长期做过
本地优先 / 中间数据格式有设计意识
AI Coding 有约束、MVP、审查、沉淀意识
能提出有价值的反问
```

### 主要短板

```text
Web / 网络基础不够系统
AI 生成实现的底层解释能力不足
算法现场实现明显偏弱
技术表达容易模糊、绕、缺少稳定顺序
性能 / 安全 / 工程化需要从经验上升为理论框架
```
